# Repository Presentation Implementation Plan

**Goal:** 为工业智能维保多 Agent 诊断平台提供面向技术面试官与使用者的、与代码一致的项目入口。

**Architecture:** README 负责项目价值、系统架构、快速开始和能力索引；架构文档解释可靠性边界；合成数据支持复现演示；GitHub 配置提供轻量文档与语法检查。

**Tech Stack:** Markdown、Mermaid、FastAPI、Python、GitHub Actions。

## 约束与设计判断

- 用户已授权连接指定远程仓库并进行 README 与简单维护；本次直接完成可审阅交付。
- 使用“工程架构 + 复现入口”的组织方式，优于仅介绍业务或罗列技术名词，便于读者沿代码核验。
- 不将设计目标写成已实现功能，不引入未经测量的准确率、吞吐量或上线规模。
- 不扩展业务功能；补齐配置加载已有依赖、忽略本地秘密、修正文档中的模型配置过时信息。
- 合成资料不代表真实工业逻辑，不包含简历中的私人联系方式。
- 新增检查仅声明实际覆盖的 Markdown 与 Python 语法，不冒充端到端测试。

## 验证重点

1. README 的 API、字段与真实路由匹配。
2. 阶段产物落盘与自动恢复、完整 Trace 的描述边界明确。
3. 点位本地校验验证路径与原文，但不声称证明 PLC 程序执行语义。
4. 诊断置信分数与点位重要性分数不被写成统计校准概率。
5. 评估仅有两条 smoke case，evidence_grounding 当前只覆盖最后一个案例。
